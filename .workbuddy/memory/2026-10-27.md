## 竞品分析：remote-china.com 如何获取"有效岗位"

用户要求分析 https://remote-china.com/ 的岗位采集方式（对标 Junes远程 的 scrape.sh 全自动模式）。

### 站点背景
- 运营者：greatghoul，西安的远程工作程序员；电鸭社区核心共建者、GDG西安组织者
- 维护 greatghoul/remote-working Awesome List 十余年；TG 频道 @remote_cn
- 纯个人站，2013 年起源于一次技术聚会

### 核心方法论（/about 页面公开）
**不是爬虫取胜，而是"半自动采集 + 人工把关"**，工具链三阶段进化：
1. 小书签（bookmarklet）：JS 抓网页信息并格式化
2. 油猴脚本：功能更复杂、可自动执行、生成二维码/分享卡片
3. Chrome 扩展：自动发布到 TG 频道（官方 API）+ 豆瓣小组（模拟网页操作）

**关键质量机制：**
- 运营者本人阅读每条 JD 并写"人工摘要"；DeepSeek AI 总结仅作补充
- 筛选标准原文："看起来不至于太离谱"
- **日均仅发布 6-10 条，有时一条都没有** ← 有效性核心
- 岗位详情页双栏展示："职位描述 人工摘要" + "职位描述 AI总结"
- UGC：注册用户投稿需审核；豆瓣小组投稿酌情采纳
- 社区举报 + 审核记录公开透明（/notes/job-report-records）
- 免责声明：招聘信息均收集自网络，是否靠谱请自行判断

### 商业闭环（积分制）
签到得积分（连续7天额外奖励）→ 投稿消耗1积分、采纳返还3积分（净+2）→ 积分解锁岗位链接/邮件推送（1积分/封，需余额≥6）→ 积分可购买（¥9.90/50，¥49.90/400）。积分既是反垃圾门槛，也降低爬虫价值。

### 技术侧
- robots.txt：Allow /jobs/，Disallow /jobs?labels=*（屏蔽标签组合页），禁 AI 训练爬虫（ClaudeBot/GPTBot/Google-Extended 等），Content-Signal: ai-train=no
- sitemap.xml 仅 146 条页面级 URL，岗位详情 /jobs/{id} 不在其中
- 有公开 API/RSS，已被第三方封装为 MCP（zc-remotechina-scout-mcp，search_jobs/get_job）

### 对 Junes远程 的启示
当前 scrape.sh 全自动（国内1100+条）量大但有噪音（需 TITLE_BLACKLIST 过滤非招聘帖）。可借鉴：
- 建立"每日精选"层（已有 jobs-featured.js 雏形），用人工/AI 摘要提升质量
- AI 摘要岗位 JD，降低用户筛选成本
- 社区举报 + 审核记录公示，提升可信度

## 落地：每日精选接入「人工把关」流程（同日实现）

按 remote-china 的半自动+人工把关模式改造精选板块，用户确认方案=审核台页面 + 双向候选来源。

### 新增文件
- **`review.html`**（根目录）：单文件人工审核台。三视图：
  1. 待审候选（pendingList）：逐条过审，可编辑写人工摘要，按钮[上线][编辑][淘汰][看原文]
  2. 岗位库提候选：切换国内库/海外库 + 关键词搜索（title/company/description），命中即[提为候选]，已提案的显示"已在候选池"
  3. 已上线：可[编辑][下线]（下线退回待审池）
- **`jobs-featured-pending.js`**：待审池 `JOBS_FEATURED_PENDING` + `JOBS_FEATURED_REJECTED`（淘汰记录，避免重复提议）
- **`.vercelignore`**：排除 review.html / jobs-featured-pending.js / money.xlsx / scripts / supabase /.workbuddy

### 关键设计
- **前端零改动**：index.html 不引入 pending 文件，getFeaturedList() 仍只读 JOBS_FEATURED，天然隔离
- **上线映射**：pending → 精选对象，自动生成 id（featured-YYYYMMDD-NN，查重递增）、date=当天、补 isNew/isFeatured/logo（按 category 映射 emoji）/work_style
- **内部字段**：`_from`（cn/global/manual）、`_srcId`（库里原 id，用于去重）序列化时自动剔除
- **序列化**：自研 jsStr/jsVal，输出单引号风格（与手写文件一致）。已用 node 验证：真实精选 6 条、抓取库 40 条抽样、特殊字符（单引号/换行/反斜杠/制表/null/中文）全部无损 round-trip
  - **坑**：初版 `if (v == null) return "''"` 会把 null 写成空串丢语义，已改为 null→'null'、undefined→跳过该字段
- **导出**：底部按钮生成完整文件（含头注释）触发下载，人工覆盖回仓库。纯静态无后端，故操作只在浏览器内存，刷新会丢 → 页面已明示"记得导出"

### 验证

- headless Chrome --dump-dom 渲染：统计正确（已上线6/待审0）、岗位库匹配 1190 条显示 60 条、无 JS 报错

### 关键认知（易踩坑）
- **「远程中文网」就是 remote-china.com**，同一站点、同一 URL。scrape.sh 注释长期用中文别名，极易误判成两个源 → 已将 16 处别名统一改为 `remote-china.com`
- remote-china **曾经是主力源**（存量 529 条），失效原因是**站点改版**

### 改版导致的失效（根因）
```html
<!-- 旧：链接就在 job-item 自身 -->
<a class="job-item" href="/jobs/2308">
<!-- 新：job-item 变 div，链接下移到子 a.job-link -->
<div class="job-item"><a href="/jobs/2308" class="job-link"></a>...
```
`soup.select('a.job-item')` 匹配 0 → 列表页下载成功(251KB/15条岗位)却解析出 0 条。

### 修复内容（scrape.sh）
1. 列表页预下载段 + 解析段：选择器 `a.job-item` → `div.job-item`，href 改从子 `a.job-link` 取
2. 薪资：`.job-description` 截断 50 字 → 独立 `.job-salary` 真实薪资
3. 日期：`date` 统一填抓取当天 DATE → 取 `<time datetime>` 前10位真实发布日，格式异常兜底 DATE
4. **删除电鸭死代码**：只有 `open('/tmp/dianyu.html')` 从无 curl 下载，每日志必报"文件不存在"；删解析块 + 合并段 `dianyu_jobs` 引用（788 行 eleduck 外链识别是 V2EX 正文逻辑，保留）

### 验证

## 新增三个抓取源：智联招聘 + Working Nomads + Himalayas（同日）

用户问能否加智联招聘、BOSS直聘 → 实测评估后：BOSS 否决、智联接入，并补两个海外合规源。

### BOSS直聘：否决（实测）
`curl` 搜索页返回 HTTP 200 但只有 **9613 字节 SPA 空壳**，零 JSON、无 `__INITIAL_STATE__`。数据需 JS 渲染 + `__zp_stoken__`（securityCheck 风控签名）才能拿到。curl 直连拿不到一个岗位 → 投入产出比极差，明确建议不碰。

### 智联招聘：可行（实测）
- `sou.zhaopin.com/?kw=XXX` 返回 347KB HTML + 内嵌 `__INITIAL_STATE__`
- 岗位在 `positionList[]`，**顶层字段即可用**：`name`/`companyName`/`salary60`/`workCity`/`positionUrl`(完整URL)/`publishTime`(精确到秒)/`number`
- **搜索词命中率实测**：`居家办公` 19/20 > `远程办公` 11/20 >> `远程` 9/20
  - `远程` 会大量命中「远程面试」陷阱（面试远程≠工作远程）+ 开票会计/物业工程经理等无关岗
  - → **最终用「居家办公」+「远程办公」双词抓取**
- 严格过滤：先剔 `远程面试`，再要求命中白名单（远程办公/居家办公/在家办公/可远程/远程工作/全远程/远程岗/线上远程/纯远程/远程授课/线上作业/远程兼职/在家工作/work from home/fully remote/remote work）
- 实测两词合并去重后 **30 条/次**

### 海外两个合规源（实测可用）
- **Working Nomads** `https://www.workingnomads.com/api/exposed_jobs/`：JSON 数组 **39 条**，字段 url/title/description/company_name/category_name/tags/location/pub_date
- **Himalayas** `https://himalayas.app/jobs/rss`：RSS **20 条**。坑：公司名在**命名空间字段** `himalayasJobs:companyName`（不是 `<company>`，最初按 `<company>` 找所以没找到）
- We Work Remotely 测过：403 Cloudflare，不可用

### 实现（scrape.sh）
1. 下载段新增 curl（智联双词 + WN + Himalayas，智联两词间 sleep 1）
2. 解析段新增三块，接在 V2EX 之后、读取现有数据之前
3. 合并段：`merged_cn` 加 `zhaopin_jobs`；`merged_global` 加 `workingnomads_jobs + himalayas_jobs`
4. **id 用 md5 而非 `hash()`**：内置 `hash()` 每次进程 PYTHONHASHSEED 随机，会导致跨天去重失效 → 新增 `stable_id(prefix,key)` 用 `hashlib.md5(...)[:10]`

### 验证
- bash -n OK；4 个 python heredoc 全部 py_compile OK
- 提取 scrape.sh 真实代码实跑：**智联 30 + WN 39 + Himalayas 20 = 89 条**
- 完整性全绿：sourceUrl 非空且唯一、id 无重复、date 格式合法、description ≤500、company 非空
- **id 跨两次独立执行完全一致**（md5 稳定性专项验证）
- 智联残留「远程面试」0 条 ✅

### 踩坑（重要，删 heredoc 代码时易犯）
用 `find('PYEOF')` 定位 heredoc 结束行会**误中开头行 `python3 << 'PYEOF'`**，导致只删掉开头、剩余 python 代码裸露在 shell 里 → `bash -n` 报 `syntax error near unexpected token '('`。
**必须匹配"整行 strip() 后完全等于 PYEOF"的行**。当时靠 `scrape.sh.bak` 备份恢复后重做。教训：删大块代码前先 `cp` 备份，且删完立刻 `bash -n` 校验。
